Crew assignment views update

Added Crew view to Labor and Logistics: All assignments, Needs crew, Full crew assigned.
Labor is full when assigned workers meet or exceed the saved crew size. Unknown or zero crew sizes remain in Needs crew.
Logistics is full when both a driver and at least one vehicle are assigned.
Views work with existing layouts, date filters, and labor search. Each board remembers its selection in this browser.
Admin problems now show the affected webhook URL, including existing failed runs. New workflow failures include webhook type and URL in their error text.

Apply the changed-files ZIP to the repository root, or use the complete project ZIP. Deploy through the existing Netlify process.
Verified: production build/syntax checks; browser checks for partial/full/unknown labor crews and assigned/missing-driver logistics.

Contract workflow update
- Dispatch booking supports Hourly (Labor) only. Contract/Demo jobs must originate in GHL or Make; imports remain supported.
- Contract rows initially show Configure project. The existing Edit Job Details screen is used; after its first successful save, the row returns to Edit Details.
- Before the first board time lock, contract jobs need saved configuration and a saved Project Schedule with a start date and at least one enabled phase. Sending the PDF is not required.
- Imported contract times are editable until this first lock. Existing contract jobs will also need this initial setup after deploying the update.
- Configuration and first-lock status are shared across dispatchers and survive daily resets. Later time edits do not require a new Project Schedule.
- The server verifies job type against GHL on detail and time saves, so GHL must be available for those operations.
Verified: 28 state/workflow tests, production build checks, and browser checks for contract booking removal, configuration labels, and first-lock behavior.

Senior-admin webhook resubmission update
- Admin > Send history > Webhook runs lists the latest 500 stored webhook runs, including EOD sheets, worker/driver notifications, job logs, hours, details/stage updates, reminders and resubmitted Project Schedules.
- Senior admins can Resubmit confirmed, acknowledged, failed or timed-out stored runs. Ordinary admins and signed-out callers cannot resubmit through the API.
- EOD resubmissions rebuild the sheet from the original saved payload, preserving that run's crew, date and hours even after the board has been reset.
- Resubmissions receive a new event ID so a previously processed event does not block an intentional re-send. A confirmation explains that downstream messages or entries may repeat.
- Each attempt and its result are recorded in the activity log. Existing board state is not changed by resubmission.
- Pending/cancelled originals cannot be resubmitted. Fresh sends and simultaneous resubmissions are blocked; a repeated request after a lost reply does not send again.
- Project Schedule history includes Resubmit saved schedule, which sends the latest saved version; resubmitted schedules then also appear in Webhook runs.
- Legacy EOD/webhook sends without a retained original payload cannot be reconstructed automatically. The existing Retry control remains available for unconfirmed effects.
- Uses the configured current webhook URL for the selected kind and displays the affected webhook in history.
Verification: production build, 38 focused state/workflow/access tests, browser verification of senior-only controls and original-run request selection. No live webhook was sent during verification.
